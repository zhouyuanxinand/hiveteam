# Security Policy

HiveTeam is a local development tool for coordinating CLI agents. It is not a
hosted service and does not provide a multi-user security boundary.

## Supported Versions

| Version | Supported |
| --- | --- |
| Latest checked-in build | Security fixes accepted during public preview. |
| 2.x | Best-effort fixes while the public preview is active. |
| Earlier versions | Not supported. |

## Reporting a Vulnerability

Use GitHub private vulnerability reporting for `zhouyuanxinand/hiveteam` whenever it is
available. Do not paste exploit details, tokens, terminal logs, private
workspace paths, or reproduction scripts into a public issue.

If private reporting is temporarily unavailable, open a minimal public issue
with the title `Security contact request` and no technical details; a maintainer
will provide a private contact path before triage continues.

Expected response during public preview:

- Initial maintainer response: best effort within 7 days.
- Public disclosure or changelog entry: after a fix is available, or earlier
  when the issue does not expose users to practical exploitation.

Please include:

- HiveTeam version or commit SHA.
- Operating system and Node.js version.
- Whether the issue affects the local runtime, packaged install, web UI, PTY
  process handling, or the injected `team` command.
- A minimal reproduction when it is safe to share.

## Local Runtime Safety

The local browser must be opened by the HiveTeam launcher. It receives a one-time
bootstrap capability that expires after 60 seconds; refreshing an authenticated
page reuses its HttpOnly session cookie. An unauthenticated request to
`GET /api/ui/session` can no longer create a session. If a runtime restart
invalidates a page, reopen it from the desktop application or enter `o` in the
interactive `hive` terminal. Bootstrap capabilities are not printed in logs.

For Supervisor MCP access, use the local toolbar's **MCP** action to copy an
authorized client configuration. The client must supply `HIVE_SUPERVISOR_TOKEN`;
anonymous Supervisor capability retrieval is disabled. Copy a fresh configuration
after restarting HiveTeam. This capability, UI sessions, desktop bridge credentials,
and launcher IPC credentials are stripped from agent environments.

Remote tunnel credentials and agent tokens do not authenticate desktop sessions.
Only the documented public preference keys are available through generic
app-state routes; internal credentials and unknown keys are rejected.

- HiveTeam binds to `127.0.0.1` by default. Do not expose the runtime port directly
  to the internet or to an untrusted network.
- Built-in presets no longer add permission bypass flags. Each agent defaults to
  a restricted execution policy; unsupported CLI/platform combinations cannot
  start under that policy.
- The local **Execution permissions** control shows requested permissions,
  actual enforcement, unsupported capabilities, and the current process policy.
  An explicit unsafe exception applies to one agent, workspace, CLI fingerprint,
  and policy revision. Such a process has the authority of the user running HiveTeam.
  Revocation changes subsequent launches; stop a running process to remove its
  existing authority.
- A local user may also remember a trusted CLI as the default for automatically
  created members. This preference is installation-wide and binds the preset and
  executable/launcher identity; each new automatic member still receives its own
  grant and audit record before launch. Manual members are unaffected. Updating
  the CLI invalidates the matching default, and revoking an existing member does
  not cause its grant to be recreated on restart. Only a local user may change
  this default; agent tokens and generic app-state writes cannot enable it.
- Only open trusted workspaces. HiveTeam intentionally gives agents access to the
  selected workspace so they can edit files and run project commands.
- Agent tokens are generated by the local runtime, injected into agent process
  environments, and intended only for local agent-to-runtime calls.
- The browser UI token is a same-machine session guard. It is not designed to
  protect HiveTeam from other processes already running as the same OS user.
- Do not paste HiveTeam agent tokens, terminal output, or workspace logs into public
  reports if they include private repository or machine details.

## Remote Access Safety

Remote access is optional and off by default. Pairing alone grants neither
workspace visibility nor write access. The local browser selects the workspaces
each device may see. A device can request specific actions for a workspace;
only a local user can approve a temporary grant, for at most ten minutes.

Grants are bound to the device, workspace, actions, and current runtime. They
expire on restart and cannot extend themselves. Removing a workspace scope or
revoking a device closes its affected connections and invalidates its grants.
Write expiry preserves authorized terminal output and acknowledgements while
rejecting further input, resize, stop, and retry messages. The terminal displays
its current read-only or temporary-write state.

Security configuration, execution-policy exceptions, and remote grant approval
remain local-only. Audit records identify the actor, action, resource, grant,
decision, and outcome without retaining raw keystrokes. A failed required audit
write prevents remote write operations.

- Pair only devices you control and revoke them when they are no longer needed.
- Pairing must be confirmed at the desktop; do not approve a code you did not
  initiate.
- Remote access does not move your workspace or agent execution to the gateway.
  The gateway relays authenticated traffic; your HiveTeam runtime and CLI agents
  still run on your machine.
- If you suspect a device, browser profile, or gateway account is compromised,
  disable Remote access, revoke paired devices, and restart HiveTeam.

## Execution Isolation Boundaries

HiveTeam delegates enforcement to verified native CLI sandbox capabilities. A git
worktree, role prompt, HTTP folder browser, or stripped environment is not an OS
sandbox. Restricted launch validation fails closed when required capabilities
cannot be established. The checked-in manual acceptance scripts record the exact
CLI version, platform, production profile, and tested tool/resume behavior; Linux
results do not establish Windows or macOS support.

Restricted Codex uses a dedicated CLI home, a minimal tool environment, explicit
filesystem roots, and blocked tool networking. Model authentication remains a
trusted CLI concern and is separated from the tool environment. HiveTeam's scoped
mailbox permits supported `team` operations without giving tools general access
to the local HTTP control plane. Reviewers receive read-only source access;
controlled worker commits use the runtime's narrow Git operation rather than
granting direct write access to Git metadata. Git history may contain previously
committed secrets; this feature does not scrub repository history.

The runtime and other unrestricted processes running as the same OS user remain
trusted. Unsafe exceptions, workspace shells, verification commands, and native
CLI internals are outside the restricted worker guarantee. Use trusted commands
and workspaces, and inspect the policy shown for the actual running process.

## Managed Execution Limits

HiveTeam reserves capacity in SQLite before preparing or spawning an orchestrator,
worker, workspace shell, or verification. Defaults are eight global executions,
four per workspace, twelve persistent workers per workspace, and one verification
per workspace. Only the local user can change these bounded limits. The Resources
panel shows actual occupancy, pending starts, and actions to free capacity.

Idle processes still hold execution capacity. Stopped workers still occupy
membership slots. Lowering a limit preserves existing processes and blocks new
admission. Each canonical data directory permits one active runtime; uncertain
processes from a previous runtime retain their reservations until absence can be
confirmed. Restart and elapsed time alone do not prove a process exited.

Close older HiveTeam versions before upgrading. The owner lock only coordinates
runtimes implementing this protocol; older shells lack persisted process records.
An old unfinished verification without a PID remains conservatively counted.

These limits count HiveTeam-managed primary executions. They do not impose CPU, RAM,
token, provider concurrency, or OS process-tree limits, and do not count agents
started outside HiveTeam or native CLI subagents.

## Out of Scope for Public Preview

- Running HiveTeam as a shared server for multiple users.
- Exposing the local HiveTeam port through a public tunnel or reverse proxy.
- Operating HiveTeam as a hardened production service.
- Sandboxing third-party CLI agents beyond the controls provided by those CLIs.
