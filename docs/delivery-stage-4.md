# 交付工作台：PR、待处理队列与分支维护

面向使用者的完整流程与界面配图见 [交付功能图文指南](delivery-guide.zh.md)。

本阶段在 `codex/delivery-workbench` 上继续扩展前三阶段。代码等待人工验收，
本项目的开发分支尚未合并到主干。

## 验收入口

| 入口 | 新增能力 |
| --- | --- |
| 活动中心 → 全部待处理交付 | 查看所有工作区的阻塞、待验证、待验收、待集成及 PR／CI 状态；按工作区和事项筛选、分页处理 |
| 验证与版本确认 → PR 与 CI | 核对仓库、分支与已验收提交；编辑描述、推送并创建草稿 PR；查看 CI 和合并状态 |
| 验证与版本确认 → 分支更新 | 将本地目标提交合并到独立分支；查看冲突文件、审阅暂存结果、完成或放弃更新 |
| 活动中心 → 保留的工作目录 | 检查已删除 Worker／工作区遗留的目录；回收满足条件的目录并保留分支 |

验收窗口按“验证、集成、PR 与 CI、分支更新”切换内容。队列中的 CI／PR 事项
直接打开 PR 页面，待集成事项直接打开集成页面，未结束的 Git 操作打开分支更新。
即使删除了最后一个工作区，活动中心的队列与保留目录入口仍可访问。

## 发布与 CI

发布要求独立工作目录、当前成功报告、当前提交的成功验证与人工验收、Worker 已停止，
且没有未完成派单。服务端会重新检查请求中的完整提交 SHA、验证 ID、仓库与分支。

首次发布需要在本机安装 GitHub CLI、用 `gh auth login` 登录，并配置 Git 远端凭据。当前支持 GitHub.com
上的同仓库 PR，仓库从 `origin` 读取。不同或多个推送目的地会被拒绝。
点击“推送并创建草稿 PR”才会产生远程写入：推送指定 SHA 到 Worker 分支，然后创建
草稿 PR。更新已有 PR 时也只推送当前验收版本，不强推，不自动合并。

发布前写入 SQLite 状态；重启会将未完成的发布标记为待恢复。重试先查找匹配的已有
PR，再决定是否创建，避免“远端已创建、本地未收到确认”时重复发布。已经创建 PR
但读取 CI 失败时，保留 PR 编号和错误，可以打开 PR 或刷新，不会丢失发布凭据。

发布、分支维护和工作区删除互斥。删除等待验证或进程退出期间也会拒绝新的发布请求，
避免远端写入后，本地发布凭据随工作区被删除。删除工作区仍保留独立工作目录。

CI 聚合 check runs 与 commit statuses，包括分页；同名 status 使用最新结果。
检查证据绑定 PR 的 head SHA。当前验收版本与远端 SHA 不一致时会明确提示。
“尚无检查结果”“运行中”“已跳过”“未知”“失败”与“通过”分别显示。
这些是已观察到的检查结果，不代表已满足 GitHub 的全部分支保护要求。

PR 页面在可见时每 30 秒刷新远端状态，也可手动刷新。队列显示已缓存状态及最近检查
时间。PR 可以处于待合并、未合并关闭或已合并状态；实际审批与合并在 GitHub 完成。

API 使用 GitHub CLI 的 [REST 请求与分页能力](https://cli.github.com/manual/gh_api)，
对应 GitHub 的 [PR 接口](https://docs.github.com/en/rest/pulls/pulls)、
[Check runs 接口](https://docs.github.com/en/rest/checks/runs)与
[Commit statuses 接口](https://docs.github.com/en/rest/commits/statuses)。

## 跨工作区队列

队列从 SQLite 对全部派单进行分类后分页，不受单工作区最近 100 条记录限制。
优先展示阻塞和失败，其次按创建时间从早到晚排列。默认每页 25 条，HTTP 接口每页
最多 100 条；工作区和状态筛选在服务端完成，总数与当前页面来自同一个数据库快照。

列表每 10 秒刷新本地记录；不会对每个条目启动 Git 进程或请求 GitHub。
打开详情时检查当前 Git 状态。已经集成的本地交付与已合并的当前 PR 会退出待处理队列。
外部编辑器直接改变分支时，列表的历史验证状态可能滞后，实际操作仍需服务端重新验证。

## 分支更新与冲突

分支更新使用保留历史的 `git merge`，将预览中的本地目标提交并入 Worker 分支。
不会自动拉取远端，不执行 rebase 或强推。Worker 必须停止、没有待处理任务、没有
正在执行的验证，且独立目录干净。目标项目目录与分支必须仍匹配创建时记录。

更新产生新提交后，旧版本验收不能用于集成或发布，必须重新验证并验收。
发生冲突时保留真实 Git 合并状态与冲突文件清单，阻止 Worker 启动、验证和发布。
用户在独立目录中编辑文件并 `git add` 后，可刷新、审阅暂存差异并提交解决结果；
也可放弃此次更新，恢复更新前的提交。放弃更新会丢弃这次合并的冲突解决内容。

合并状态与 SQLite 记录跨重启保留。只允许继续或放弃 Hive 记录且 SHA 匹配的合并。
外部工具开启的 rebase、cherry-pick 等未完成操作也会阻止验证和 Worker 启动，
需要在原工具中完成或放弃。工作目录中的代码不会被自动猜测、改写以解决冲突。

## 目录回收

新的持久记录独立于 Worker／工作区的生命周期，旧的独立目录绑定也会迁移进来。
删除 Worker 仍然保留代码。只有绑定解除、进程停止、目录属于 Hive 管理路径、
Git 仓库与分支身份匹配、没有未结束 Git 操作或未提交／未跟踪文件，且全部提交已
进入本地目标分支时，回收按钮才可用。

回收请求再次核对完整源 SHA 与目标 SHA，然后调用非强制的 `git worktree remove`。
分支和提交继续保留。未跟踪的协调文件或用户笔记同样需要先检查并保留，不会强制删除。
在 Git 已移除目录、数据库尚未更新之间中断，重启后会核对目录与 Git 注册记录并修复
回收状态。原仓库丢失、路径变化或检查失败会显示原因并保留记录。

## 范围与后续

本轮已落地 PR／CI、全局待处理队列、受控分支更新、冲突处理及人工目录回收。
以下能力尚未实现：GitHub Enterprise／其他代码托管平台、fork PR、自动远端拉取与
rebase、冲突自动解决、定时自动回收、远端分支删除，以及在工作台中审批／合并 PR。
经 squash 合并但尚未进入本地目标历史的分支，也不会被自动判定为可回收。

SQLite schema 升级至 42。新增 HTTP 边界继续使用 snake_case，Agent 状态仍为
`idle`、`working`、`stopped`，测试没有替换生产 PTY／Git／SQLite 的运行路径。

发布测试使用自建本地 bare Git 远端及本地 GitHub HTTP 服务。浏览器预览使用明确
标注的演示数据，不向实际 GitHub 仓库发布。

核心流程、失败恢复、队列分页及 12 项界面交互的针对性测试已通过。

- `pnpm build`：生产 TypeScript 编译及前端构建通过。
- 完整回归：220 个测试文件通过、2 个文件按既有条件跳过；1107 项测试通过、
  5 项按既有条件跳过，没有失败。

一起通过，确认重叠发布被拒绝、远端没有新分支，删除结束后本地工作目录仍保留。

无横向溢出、无浏览器异常，键盘焦点可见；本阶段单次设计检测的
